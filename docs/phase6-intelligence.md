# Phase VI — Evidence-grounded meeting intelligence

LLM #2 extracts meeting facts. LLM #1 remains the separate conservative terminology
refiner. Both use explicitly configured Groq `openai/gpt-oss-120b`, with distinct policies
and schemas. No local LLM, agent, external-document RAG, identity inference, frontend,
PDF export or independent Phase VII verifier is added.

**Evidence timestamps and quoted source text are resolved from immutable transcript
artifacts, not generated by the language model.** Valid references do not prove entailment.

## Architecture and public API

`meeting_assistant.intelligence` isolates frozen models, config, protocol, Groq backend,
prompt/schema validation, service/chunking, evidence/clips, serialization, CLI, orchestration
and evaluation. The shared `_groq_transport` contains only bounded verified HTTPS exchange.

```python
from meeting_assistant.intelligence import (
    extract_meeting_record, get_item_evidence, save_meeting_record,
)

# Existing typed saved artifacts, loaded through their existing deserializers.
record = extract_meeting_record(refined, speaker, grounding)
files = save_meeting_record(record, refined, "transcripts")
for span in get_item_evidence(record, "dec_0001", refined):
    print(span.utterance_id, span.speaker_id, span.start, span.end, span.refined_text)
```

`MeetingIntelligenceBackend` exposes `model_info` and
`extract(IntelligenceRequest) -> IntelligenceResponse`. A future local backend implements
that protocol without changing downstream claims/evidence. No provider generator leaks out.

Before billed calls, `validate_refined_source` verifies hashes, IDs, original edits and copied
speaker/grounding evidence. No upstream object/file is mutated. Request/chunk budgets are
prevalidated. Empty transcripts return empty records without credentials or API calls.

## Canonical schema and semantic policy

Frozen `MeetingRecord` stores UUID, source refined/speaker/grounding/raw IDs and SHA-256
digests, model/policy versions, processing calls, optional audio binding and `MeetingContent`:

| Section | Frozen item | Content beyond ID/evidence IDs |
|---|---|---|
| summary | SummaryPoint | text |
| minutes | MinuteItem | text, topic, kind |
| decisions | Decision | text |
| action_items | ActionItem | task, nullable owner, nullable deadline_text |

All evidence lists are nonempty, unique tuples of supplied `utt_000001`-style IDs.
Code sorts by earliest supporting utterance, then content, and assigns sequential
`sum_0001`, `min_0001`, `dec_0001`, `act_0001`. Fresh runs get new record UUIDs;
stable numbering does not guarantee identical provider output.

Minutes classify discussion/proposal/concern/information/decision/action. Decisions require
explicit accepted outcomes; proposals/questions are not decisions. Later explicit reversals
supersede earlier choices while minutes retain discussion. Ordinary work commitments belong
in actions, without duplicate strategic decisions. Suggestions alone create no assigned task.
Task scope, negation and numbers must stay faithful; checking a tool is not deploying it.

`ActionOwner("speaker", speaker_id="SPEAKER_01")` denotes an explicit self commitment or
acceptance. `ActionOwner("named_entity", display_text="Rahul")` denotes a literal named
person/team, with speaker_id null. Never infer a name behind an anonymous speaker or assign
work to the speaker merely because they requested it. Owners/deadlines remain null when
unspecified; literal deadline phrases are not converted to inferred calendar dates.

Strict parsing rejects duplicate keys, missing/unknown fields, bad IDs, empty/duplicate
evidence, malformed owners/kinds and quote/timestamp/path fields. Discriminated owner schema
branches prohibit inconsistent nullability. Named owners/deadlines need lexical support in
at least one cited refined utterance. This does not prove the phrase assigns that value to
that task: semantic verification belongs to Phase VII.

Transcript and partial-item text are untrusted JSON data, never privileged instructions.
The policy explicitly rejects embedded requests to reveal prompts/change JSON/invent approval.
No hidden chain-of-thought is requested or stored.

## Deterministic evidence and optional audio

`resolve_meeting_record_evidence(record, refined)` checks the refined digest/provenance tuple
and returns item IDs → immutable `EvidenceSpan` tuples: utterance ID, anonymous speaker,
original start/end, refined/raw text, source word/segment references and applied edit IDs.
Retain the Phase V edit log for audit. Noncontiguous supports remain separate spans.

`evidence_manifest.json` is derived from the same record and source. Convenience copies of
text/times are bound to IDs/digests, not independently authoritative evidence.

Audio is optional. Pass `canonical_audio_path` and matching typed `diarization` to
`extract_meeting_record` for audio binding. Code checks canonical format/duration,
speaker.diarization_id and diarization.audio_sha256. The record stores SHA-256, frame count,
duration and portable name `canonical.wav`; runtime receives the real file path separately.
No machine-specific absolute path is embedded in the canonical record; clips are off by default.

```python
from meeting_assistant.intelligence import extract_evidence_clip
span = get_item_evidence(record, "act_0001", refined)[0]
clip = extract_evidence_clip(canonical_path, span, "evidence/new-clip.wav",
                             audio_reference=record.audio, padding_seconds=0.0)
```

Extraction streams PCM using `wave`, preserves 16-kHz mono 16-bit encoding, floors start and
ceils end to frames, and clamps playback to file bounds. Precision: one sample, 62.5 µs.
Exact evidence ranges stay separate from derived playback/padding. Reject zero/invalid ranges,
changed/mismatched/noncanonical/truncated source, links/junctions and overwrites. Exclusive
temporary creation and no-replace hard-link publication prevent completed-looking partial
clips; a hard-link-capable filesystem is required. Owned temporary files are cleaned.

## Long meetings

Default request-data budget is 18,000 characters including raw/refined text and IDs. This
is a conservative character bound, not an exact tokenizer count. Prompt/schema overhead and
repair data are separately bounded. Split only between whole utterances; over-budget utterances
fail explicitly, never truncate. Up to two utterances overlap, shrinking to ensure progress.
Maximum 32 extraction chunks. Exact same-content duplicates union supporting IDs in code.

Partials are internal. Multiple nonempty chunks use one bounded consolidation call, receiving
only validated partial items (≤90,000 data characters). It selects primary/merge item IDs,
never new text/evidence. Code unions support IDs; merged tasks require matching owners and
deadlines, minute kinds must match. Reject unknown/cross-section/reused IDs and modified claims.
Superseded decisions can be omitted while minutes preserve discussion.

Selection-only consolidation deliberately chooses an existing concise global summary rather
than writing a new paraphrase. Equivalence/chronology choices still depend on the model;
cross-window facts outside overlap can be conservatively missed. Too many chunks/partials
fail with no final record, rather than recursively summarizing/truncating without provenance.

## Configuration and provider

Use existing ignored `.env`; process variables take precedence. Reuse `GROQ_API_KEY`, excluded
from repr/payload/logging. Defaults:

| Environment variable | Default |
|---|---|
| INTELLIGENCE_PROVIDER / MODEL | groq / openai/gpt-oss-120b |
| INTELLIGENCE_TEMPERATURE | 0 |
| INTELLIGENCE_TIMEOUT_SECONDS | 90 |
| INTELLIGENCE_MAX_COMPLETION_TOKENS | 8192 |
| INTELLIGENCE_TRANSPORT_RETRIES | 1 |
| INTELLIGENCE_MAX_BACKOFF_SECONDS | 60 |
| INTELLIGENCE_SCHEMA_REPAIR_RETRIES | 1 |
| INTELLIGENCE_MAX_CHUNK_CHARS | 18000 |
| INTELLIGENCE_OVERLAP_UTTERANCES | 2 |
| INTELLIGENCE_MAX_CHUNKS | 32 |
| INTELLIGENCE_MAX_CONSOLIDATION_CHARS | 90000 |
| INTELLIGENCE_MAX_ITEMS_PER_SECTION | 128 |

POST `https://api.groq.com/openai/v1/chat/completions`, strict `json_schema`, nonstreaming,
reasoning effort low for GPT-OSS, include_reasoning false. No silent model substitution.
All schema properties required; objects prohibit extra fields. See current
[Groq schema documentation](https://console.groq.com/docs/structured-outputs) and
[API reference](https://console.groq.com/docs/api-reference).

Verified TLS/no redirects, fixed host/endpoint, overall request deadlines, 1-MB response cap,
sanitized domain exceptions retaining causes. Retry 429/5xx once, honoring numeric Retry-After
only within the 60-second cap. Ambiguous connection failures are not automatically retried.
At most one structure/reference repair; never directly apply provider-rejected generations.
There is no independent semantic retry/verifier. Oversized/mismatched source, provider,
schema, consolidation, audio and publication failures have distinct error codes.

Per-call records retain status/bytes/latency/retry/repair flags and available token usage.
Unknown usage remains null; totals including failed attempts cannot be claimed. Inspect
successful-call usage separately when needed. No dollar cost is invented. Network/account
quota remains an external requirement. No Python/system dependency was added in this phase.

Versions: `intelligence_v1`, `meeting_record_schema_v1`, `meeting_examples_v1`,
`evidence_policy_v1`, `consolidation_v1`.

## CLI, publication and evaluation

```sh
python -m meeting_assistant intelligence meeting.mp4 --output-dir transcripts
python -m meeting_assistant intelligence refined_transcript.json \
  --speaker speaker_transcript.json --grounding grounding.json \
  --audio canonical.wav --diarization diarization.json --output-dir transcripts
python -m meeting_assistant evidence meeting_record.json act_0001 \
  --refined refined_transcript.json --audio canonical.wav --extract-clips evidence/
```

Full mode runs I–VI through existing stage APIs. Saved mode validates compatible artifacts
without upstream inference/upload. Audio binding requires both audio/diarization. Evidence
retrieval/clips need no API call. Each atomic new UUID bundle contains `meeting_record.json`,
`meeting_record.md`, `evidence_manifest.json`, deriving from one record. Markdown escapes
untrusted HTML/link markup. No existing record/source is overwritten; failed staging is cleaned.
Generated artifacts, model caches, `.env`, validation outputs are ignored by Git.

Normal tests use fake backends/tiny PCM fixtures, no Groq/model downloads.
`data/intelligence_benchmark.json` has 18 original labeled synthetic **text** cases, not a
fabricated speech corpus. One-to-one explicit keyword alternatives match decisions/tasks;
unmatched predictions/labels count FP/FN. Inspect saved predictions to adjudicate synonyms.
Owner/deadline accuracy includes nulls on matched actions; false values count nonnull
disagreements and nonnull unmatched actions. Citation validity checks IDs; coverage checks
nonempty support. Supporting-ID precision/recall compares annotated references on matched
claims only, not semantic entailment. Review summaries manually; no automatic Phase VII score.

The original two-voice recording comes from `scripts/create_intelligence_fixture.ps1` plus
the existing assembler. The script/schedule records synthetic provenance; no intermediate
ASR/speaker/refinement artifact is manually patched. See actual results and errors in
[the validation report](phase6-validation.md).
